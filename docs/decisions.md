# Decision log

One entry per non-obvious choice: what we chose, the main alternative, and why. Kept short on purpose; it feeds interview prep.

| # | Date | Decision | Alternative considered | Why |
|---|---|---|---|---|
| D1 | 2026-11-23 | Mixed graph: only Supervisor, Retrieval (query rewrite) and Composer call an LLM; Compliance, Approval, Memory, Tool Execution are deterministic code | Seven LLM agents (literal brief); one ReAct agent | Agent on a live call needs answers in seconds (2–3 LLM calls vs 6–9); deterministic guards are testable; still 7 units with contracts. ReAct fails the multi-agent criterion. |
| D2 | 2026-11-23 | Two graphs: a chat graph that never pauses, and a per-case graph that pauses at approval | Pause inside the chat run | Approval takes hours; the agent needs the answer and script while the customer is on hold. |
| D3 | 2026-11-23 | All refunds/credits need approval; matrix decides approver tier, other risky actions and refusals | Amount threshold only | Tapas's rule; matrix keeps the gate's logic non-trivial and testable. |
| D4 | 2026-11-23 | Copilot proposes actions; agent confirms with "Send to supervisor"; amount always from transaction lookup | Draft only on explicit request; amount from customer's words | Less agent effort, human stays in charge; a customer-stated amount can't drive an approval tier. |
| D5 | 2026-11-24 | LLM never does date/₹ arithmetic: a pure-function calculator returns figures plus rule ids | Let the Composer reason over policy text | Arithmetic over working-day calendars is where LLMs fail silently; rule ids make answers auditable. |
| D6 | 2026-11-24 | Implement both RBI liability regimes, selected by transaction date (R17 before 1 Jan 2027, R26 on/after) | Only one regime | The 2026 Directions take effect 1 Jan 2027, during the project's life; effective-dating is how banks handle rule changes. *(Chosen by Tapas, 2026-11-24.)* |
| D7 | 2026-11-24 | One YAML rules file is the source of truth for the matrix, calculator and TAT table; every RBI figure traced in `docs/rbi-sources.md` | Hard-code figures in Python; derive rules from documents with an LLM | Reviewable diff when a rule changes; no LLM in the loop for regulatory numbers. |
| D8 | 2026-11-24 | Calculator refuses unconfirmed inputs (card-not-present TAT) instead of guessing | Use a plausible default | A wrong regulatory figure is worse than a refusal in a bank. |
| D9 | 2026-11-24 | Working-day calendar: Sundays, 2nd/4th Saturdays and fixed national holidays only (illustrative home branch) | Full state-wise holiday list | Real lists vary by state and year; the mechanism is what's being shown. Stated as a limitation. |
| D10 | 2026-11-24 | BANKING77 copied into the repo from PolyAI's GitHub (CC BY 4.0) instead of `load_dataset("PolyAI/banking77")` at run time | Hugging Face download during ingest | Same data; clean-machine startup no longer depends on the HF Hub. |
| D11 | 2026-11-24 | A deterministic "fake" lexical embedder for tests and offline runs; OpenAI `text-embedding-3-small` in the real stack | Mock the OpenAI client; require a key for tests | Pipeline and retrieval tests run in CI with no key and no cost; the fake is lexical, so it is never used for quality numbers. |
| D12 | 2026-11-24 | Chunk by `##` sections up to ~600 tokens, title prefixed to every chunk | Fixed-size sliding windows | Policy rules stay whole; title prefix makes each chunk self-describing for citation. Most Kestrel docs are short, so many are a single chunk (below the brief's 400-token floor); stated as a deliberate trade-off. |
| D13 | 2026-11-24 | Date-scoped retrieval: policy chunks carry `applies_to_txn_before/on_or_after`; search filters by the transaction date; superseded docs excluded unless asked | Let the LLM pick the right version | Version mistakes are the most dangerous RAG error in regulated work; a filter makes it impossible rather than unlikely. |
| D14 | 2026-11-24 | Ingest is idempotent by content hash; mock data is seeded once unless `RESEED=1` | Re-ingest on every start | No re-embedding cost on restart; the approval-restart demo doesn't wipe its own state. |
| D15 | 2026-11-24 | Enron sample built by streaming the CMU tarball and stopping at N messages; output committed | Download and extract 1.7 GB | Reviewer never downloads the archive; builder needs only one streamed pass. |
| D16 | 2026-11-24 | PII is masked at the API boundary; the raw note lives only in memory between `POST /chat` and `GET /stream` (≤120 s) | Mask inside the `compliance_in` node | LangGraph checkpoints the graph *input* before the first node runs, so masking in a node would still store the raw card number. A test reads the checkpoint tables to prove it. Cost: a run is lost if the app restarts in those seconds. |
| D17 | 2026-11-24 | Case and approval rows are written in one transaction on "Send to supervisor"; the case graph starts after; `reconcile()` at boot covers both crash windows (case without checkpoint; decision without resume) | Create the approval row inside the interrupted node | The supervisor queue never shows a case the graph doesn't know about, or vice versa, and each crash window has a test. |
| D18 | 2026-11-24 | Every case-graph side effect (credit, notification) is idempotent by `case_id` (unique key, `ON CONFLICT DO NOTHING`) | Exactly-once via a distributed transaction | LangGraph re-runs an interrupted node from its start, and a crash can land between a write and its checkpoint. Idempotent writes make "at least once" safe. |
| D19 | 2026-11-24 | A decision is recorded with `UPDATE … WHERE state='pending' RETURNING`; the loser gets 409 with the winning decision | Check graph state, or a row lock held during resume | One SQL statement decides the race; no lock is held across an LLM-free but still slow resume. |
| D20 | 2026-11-24 | Whether to draft a credit is decided by code (intent + transaction + calculator), not by the Supervisor's `proposed_action` | Trust the LLM field | Observed on the hero case: gpt-5.4-mini proposed `card_block` for an unauthorised payment, so no credit was drafted. The calculator, not the model, knows whether a credit is due. |
| D21 | 2026-11-24 | On tools/action routes, tools run *before* retrieval; retrieval filters by the transaction date and gives chunks of the intent's governing policy (`rules/intents.yaml`) a +0.1 score boost | Retrieval first, as the brief's diagram draws it; pure vector ranking | The liability regime depends on the transaction date (D13). Without the boost the hero query ranked the chargeback SOP above the liability policy. Both raw and boosted scores are traced; M4's ablation measures the boost. |
| D22 | 2026-11-24 | Retrieved chunks are screened with the same injection heuristics (document mode); a flagged chunk is quarantined whole and logged | Strip only the offending line; trust the corpus | The acquirer-bulletin trap ranked #1 for the hero query before this. Whole-chunk quarantine loses that chunk's legitimate text; refining is M3 work. |
| D23 | 2026-11-24 | The customer-facing script is a deterministic template filled from the calculator and tools; the LLM answer is for the agent only | Let the Composer write the script | The script is what the customer hears, with ₹ and dates in it (D5). It follows KB-SCRIPT-FRAUD word for word. |
| D24 | 2026-11-24 | Langfuse v3 self-hosted with SeaweedFS as its S3 store | MinIO (`cgr.dev/chainguard/minio`, Langfuse's reference compose) | MinIO no longer publishes images on Docker Hub; SeaweedFS keeps every image on one registry for clean-machine startup. Trade-off: less familiar than MinIO. |
| D25 | 2026-11-24 | `gpt-5.4-mini` with `reasoning_effort=none` for Supervisor and Composer; `gpt-5.4-nano` for the query rewrite | `gpt-4.1-mini` | Measured ~1 s vs ~2 s per short call. Hero run ≈5 s end to end, ₹0.10. M4's model comparison decides for real. Prices in `kestrel/llm.py` are unverified for the 5.4 family. *(Accepted by Tapas, 2026-11-24: keep the guessed prices, marked unverified; no ₹ cost figure is quoted in the report until they are checked.)* |
| D26 | 2026-11-24 | Composer tokens stream immediately; the output check runs after and can replace the answer (`replace_answer` event) | Buffer the whole answer, check, then send | Buffering adds ~2 s of blank screen while a customer waits. A replaced answer is visible and logged, and it is rare. |
| D27 | 2026-11-24 | The server enforces the approver tier on every decision (403 if a team lead approves a ₹2L case) | Trust the UI's approver picker | An approval gate that the client can bypass is not a gate. |
| D28 | 2026-11-24 | The calculator assumes third-party fault unless the customer says they shared OTP/PIN/card details; the answer tells the agent to confirm | Refuse to calculate until fault is confirmed | Matches the call script (block first, then ask); the shadow credit is provisional anyway, and the assumption is shown in the UI and on the case. *(Accepted by Tapas, 2026-11-24; a compliance reviewer may push back on this default, so it stays flagged on every draft.)* |
| D29 | 2026-11-24 | Langfuse trace id is derived from the run or case id; each request opens a named root span | Keep trace context in memory | A case's spans from before and after a restart land in one trace without any in-process state. |
| D30 | 2026-11-24 | Retrieved text is sanitised line by line (lines scoring ≥0.5 as instructions to the model, and HTML comments, are dropped); the rest of the chunk is kept | Quarantine the whole chunk (M2), or trust the corpus | The acquirer bulletin's reason-code table is useful; only its hidden line is hostile. Removed lines are in the trace. |
| D31 | 2026-11-24 | Job queue in Postgres with `FOR UPDATE SKIP LOCKED`, a 5-minute lease, exponential backoff and a partial unique index for dedupe | Redis + Celery/RQ | One fewer service for clean-machine startup; at-least-once with idempotent handlers is enough for a scan, a sweep and a summary. |
| D32 | 2026-11-24 | Enron scan = rule-id'd regex flags, with legal-footer matches excluded; snippets masked | LLM classification of each email | 2,000 emails in ~1 s at no cost, and each flag is explainable. Footer exclusion cut "delete this email" flags from 25 to 1. Precision is unmeasured; flags are for human review. |
| D33 | 2026-11-24 | TAT sweeper marks `at_risk` within 2 working days of the RBI-derived due date and `breached` after it; a breach drafts one grievance escalation (no approval) | Escalate at risk too | Escalation is for breaches (KB-SOP-ESC); at-risk cases rise to the top of the queue instead. The status update is guarded on the old status so a decided case is never overwritten. |
| D34 | 2026-11-24 | The agent states the caller's identity-verification level on each request (KB-SOP-IDV); code enforces it: block needs 1, any draft needs 2 (and KYC complete), contact changes need 3 | Ask the LLM to judge verification from the text | Verification is a fact from the call, not something to infer. The API default is 0 (nothing allowed), so a client that forgets it fails safe. |
| D35 | 2026-11-24 | A borderline injection score (0.5–1.0) gets one `gpt-5.4-nano` judgement; clear scores never call a model | Judge every input; or block every borderline | Keeps the hot path model-free for normal notes and avoids blocking an agent who quotes a fraudster. |
| D36 | 2026-11-24 | Session summary refreshed by a worker job after each run (dedupe per session) | A summary node in the chat graph | Off the hot path: the agent's answer never waits on it. The Supervisor gets the summary on the next message. |
| D37 | 2026-11-24 | Supervisor prompt routes general policy questions on in-scope topics to `rag` with the nearest intent | Treat in-scope intents as customer problems only | Found by the end-to-end run: "what is the liability if reported after 5 days?" was refused as out of scope. | D38 | 2026-11-25 | One credit per transaction, enforced when the credit posts (partial unique index on `mock_credits.txn_id`); a second approved case for the same payment fails with the existing credit id | Rely on the draft-time duplicate check; or return the first case's credit as if it were this case's | Found in review (CodeRabbit on PR #2): two drafts for one payment both pass the draft-time check while the first is still awaiting approval. | D40 | 2026-11-25 | Model prices taken from OpenAI's model pages (gpt-5.4-mini $0.75/$4.50, gpt-5.4 $2.50/$15, gpt-5.4-nano $0.20/$1.25 per 1M tokens); ₹ figures use an assumed ₹88/USD and say so | Keep the M2 estimates | The M2 figures (D25) were guesses and 2–4x too low, so every earlier "₹0.10 per run" claim was wrong; the eval now measures ≈₹0.23. gpt-5.4-nano (the rewrite and judge model) is marked *Deprecated* on its page: replace it before production. |

| D48 | 2026-11-25 | The LLM no longer decides refusals on its own.
